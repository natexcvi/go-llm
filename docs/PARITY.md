# Pydantic AI Harness coverage

The comparison is pinned to **pydantic-ai-harness 0.73.0**, released November 24, 2026, and its matching **pydantic-ai-slim 2.73.0**. The reference wheel has 88 documented capability directories. This is a partial native Go port. The presence of an interface or an MCP endpoint does not establish behavioral parity. [Pinned release](https://pypi.org/project/pydantic-ai-harness/0.73.0/) · [Upstream capability guide](https://pydantic.dev/docs/ai/harness/)

## Cross-checked behaviors

These cases ran independently against the pinned release with its FunctionModel. The Go suite checks the same final output, the values received by the real tool handler, and the number of model requests. [Go conformance tests](../capabilities/conformance_test.go)

| Scenario | Final output | Tool executions | Model requests |
| --- | --- | --- | --- |
| One output refinement, with scripted answers `draft` and `final` | `final` | None | 2 |
| Two lookup calls with a per-tool budget of one | `complete` | First argument only | 3 |
| Repair a single-quoted argument object with a trailing comma | `repaired` | Integer 3 | 2 |

A second check against the pinned release verified that pruning call ID `result` leaves `[tool result pruned] needle` in history and completes in three model requests. Email, Luhn-valid card and OpenAI key fixtures produced the same redaction labels in both implementations. [Pruning tests](../capabilities/compaction_test.go) · [Redaction tests](../capabilities/redaction_test.go)

## Native coverage

The entries below describe the implemented behavior. A row can cover part of an upstream capability. Provider fixtures exercise the protocol locally. Deployment-specific authentication and service behavior require separate verification.

| Upstream capability family | Go implementation | Differences and scope |
| --- | --- | --- |
| Coder, Researcher, SubAgents, Advisor | Coder and Researcher presets, named delegate roster, self-delegation, per-delegate model menus, timeouts and call limits, shared usage and forwarded child events | Roster tests cover inherited authorization, aggregate limits and deferred child resume. Coder keeps its read-only explorer. Legacy single-tool delegates have independent limits. Background steering, disk-defined rosters, child workflow activities and lifecycle controls remain open. |
| FileSystem, RepoContext, Skills, Shell | Rooted reads, atomic writes, exact edits, listing, grep, repository instructions, layered YAML skill catalogs with selection, duplicate policies and on-demand resource reads, argv execution | Shell working-directory persistence, comprehensive shell policy, ripgrep modes, secret-file rules, and some file formats differ. Bundled reads currently require a rooted local workspace, embed.FS, or a backend implementing confined reads. |
| DockerContainer, SSHWorkspace | Docker/Podman bind-mounted command execution, SSH commands and SFTP file tools | A real Docker container and a local SSH/SFTP server exercise commands and files. Container commands share files and use fresh containers. SSH requires a caller-owned connection and server-side isolation for hostile concurrent writers. |
| BubblewrapSandbox, SpritesSandbox, OpenSandbox | Local Bubblewrap command isolation and workspace adapters for caller-provisioned Sprites and OpenSandbox instances using their Go SDKs | OpenSandbox command execution and file reads and Sprite file reads have local HTTP contract tests. Bubblewrap builds. This test host denies namespace UID mapping, so live isolation remains unverified. Managed provisioning, lifecycle and live cloud verification are outstanding. |
| ArtifactScanning, PromptInjectionDefender, LabelCrossModelHistory, WarnOnCacheBusts | Artifact checks on memory and skills, reporting or replacement of flagged tool results, previous-model attribution and cache-counter warnings | Pattern coverage, provenance granularity, cache baselines and upstream telemetry differ. |
| AWS Lambda, Azure Durable Task | Native SDK adapters record a model request or top-level tool call per step and support external approval callbacks or events | Lambda replay is tested with the SDK's local runner. An Azure Durable Task worker backed by PostgreSQL exercised event-based approval and completion. Capabilities are reinstalled at step boundaries. Step payload limits apply, nested tools run inside their parent's activity, and live cloud deployments are unverified. |
| Absurd, PGTask | Native Absurd step and event APIs, pgtask checkpoint reads and commits with an active lease | PostgreSQL integration tests cover an Absurd worker suspending for approval, pgtask rejecting a stale lease and replaying a completed model request. The host manages worker registration, leases and queue lifecycle. |
| Planning, Memory, ConversationSearch, StepPersistence | Task lists, prerequisites, scoped notebooks with bounded user-role snapshots, read/search limits and main-file protection, BM25 transcript search, serializable checkpoints, in-memory, directory and SQL stores | The store contract passed against SQLite and PostgreSQL 16. Built-in stores support bounded notebook reads. Custom stores can implement BoundedStore to avoid fetching whole documents. Optimistic notebook edits, mutation replay, migrations and distributed durability differ. |
| Guardrails, Goal, Permissions, AskUser, ApprovalReviewer, ToolCallJudge, DenyUnanswered | Ordered input/output/tool-result text filters, credential and PII redaction, buffered output screening, goal verifier, per-call decision callbacks, interactive questions, reviewed approval, deny-on-defer | Per-call approvals survive checkpoints. AskUser uses a synchronous callback. Detectors cover vendor tokens, PEM blocks, common PII and checksum-validated cards and IBANs. Detector edge cases, structured verdicts, typed output replacement and upstream telemetry differ. |
| DetectLoops, ToolBudgets, ToolOutputLimits, SpendLimits, ReportRemainingBudget, WrapUpAtLimits | Consecutive-repeat detection, repeat suppression, call budgets, truncation and content-addressed spill, scoped spend ledger, request and token limits | Spend pricing comes from the application. Upstream external spend ledgers, default loop nudges and all budgeting modes are outstanding. |
| Compaction, CurrentTime, SystemReminders, ReportStaleFiles | Persistent ordered tiers with message, estimated-token and fraction triggers, usage reports and warnings, batched clearing, keyed read deduplication, targeted pruning, pinned exchanges, model summaries, relevance ranking, fallback, receipts, manual compaction, and native OpenAI Responses/Anthropic compaction | Fixtures cover signed/encrypted replay, server thresholds, interrupted approvals and shared helper budgets. Local strategies trade prefix-cache reuse for context space. Token estimates, window resolution, relevance caching/concurrency, background summarization, cross-provider bridging and telemetry differ. Legacy standalone window/clear/clamp helpers still edit the request view. |
| SmartSearch, BackgroundTools, Peers | BM25 source search with optional relevance judge, scoped background Go handlers, in-process peer messaging | Search chunks, job persistence, mailbox retention and transport differ. |
| ToolBridge, ModelRouter, RepairToolArguments, RefineOutput, RequireVerification, TrajectoryJudge, ReportToolErrors | Tool discovery and dispatch, model selection per request, JSON repair, bounded review rounds, verification gate, trajectory feedback and error callbacks | ToolBridge forwards authorization to the underlying tool. Verification checks a successful named tool handler. Upstream model routing, verification heuristics and instrumentation differ. |
| CodeMode | A Go-built Starlark interpreter runs in WebAssembly, calls typed Go tools, and returns the final expression and printed output. Nested calls share the parent policy, middleware, events and usage limits. The default REPL retains variables and function definitions across snippets, supports restart and resumes from a checkpoint. | A program with two nested calls pauses and resumes without repeating the first tool. Starlark differs from upstream Monty Python. Cross-run REPL storage, async gather, module imports, early/speculative execution, IPython and the upstream exception protocol are outstanding. |
| DynamicWorkflow | A model-written Starlark program calls named child agents, combines their results, and shares a parent-run call budget | Tests cover composition and the shared limit. Calls are sequential. Parallel gather, dynamic discovery, child usage forwarding and upstream Python semantics differ. |
| BrowserUse | A browse_web tool delegates a goal to a child agent with a fresh Chromium tab, an independent step budget, optional review and inherited authorization | Tested with separate parent and child models. The upstream browser-use planning, vision and judging implementation differs. |
| CapabilityCreation | Author, compile-check, list and disable named Starlark tools in a scoped store, with explicit next-run activation through LoadActive | Tested across independent agent runs. Authored scripts transform structured inputs. Upstream Python capability classes, lifecycle hooks, source imports and manifest formats are outstanding. |
| Playwright Browser | Pure Go Chromium DevTools client, one tab per run, origin-filtered HTTP requests, navigation, form input, clicks, waits, scrolling, text and PNG capture | A real Chromium test fills a form and blocks an off-origin subresource. Accessibility handles, additional tabs, browser-wide egress controls and several upstream actions are outstanding. |
| Media | URL and binary image input, content-addressed image checkpoints over memory, directory or SQL stores and verified rehydration | Checks cover wire formats for both model transports, canonical SHA-256 URIs, round trips and corruption. Upstream wire markers, arbitrary payload walking, audio/video, S3 and MongoDB stores are outstanding. |
| PydanticAIDocs, Macroscope, StackOne | Six docs topics, per-run cache and model-alias expansion, Macroscope CLI review parsing, account-scoped StackOne MCP with action glob filters and search/execute mode | Tests cover docs alias expansion, Macroscope CLI parsing and StackOne authentication and action filtering against a local TLS MCP server. Macroscope requires an authenticated workspace CLI and StackOne accepts per-run credentials. Hosted account behavior remains unverified. |
| Keenable, Exa, You.com | Native HTTP search and page retrieval, You.com synchronous research | Keenable has local wire tests. Service-specific advanced search, async research, rich citation metadata and live service verification are outstanding. |
| GitHub, Linear, Notion, Slack, Google Workspace, Grain, Day AI, Pylon, PostHog, Ordinal, Logfire MCP | Native MCP initialization, paginated discovery, calls, caller-supplied auth, tool prefixes, filtering, result handling and session teardown | Local MCP tests cover discovery, filtering and execution. Hosted endpoint presets share this client. Upstream service-specific credentials, browser OAuth enrollment and tool policies are outstanding. |

The Go runtime also provides a typed model loop, JSON Schema generation and validation, streaming OpenAI Chat Completions, OpenAI Responses and Anthropic Messages, model fallback, and deterministic model injection. Provider catalogs, multimodal outputs, and the complete Pydantic AI core API extend beyond the verified harness surface.

## Outstanding ports

| Area | Upstream capabilities requiring additional implementation |
| --- | --- |
| Managed and isolated workspaces | BoxdSandbox, BoxLiteSandbox, DaytonaSandbox, E2BSandbox, KubernetesSandbox, ModalSandbox, RenderSandbox, SmolSandbox |
| Workflow and durability engines | Render Workflows |
| Execution environments | IPythonCodeMode |
| Artifacts and integrations | LocalStack, Pixeltable, Logfire managed prompts |
| Policy and provider context | PromptInjectionDefender semantic detection and provider-specific policies |

The upstream wheel also includes experimental modules and compatibility aliases. They have no independent parity claim here.
